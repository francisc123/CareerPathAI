# CareerPath AI — Jira Backlog & 4-Week Sprint Plan

## Strategic Overview

### Critical Path Logic

The 20-day plan is built around one hard constraint: **no developer can integrate with a service that doesn't exist yet**. This forces a strict foundation-first approach in Week 1.

The execution strategy has three phases running in parallel from Day 1:

- **Francisc** owns the critical path. Every other developer depends on his work. He builds Docker infrastructure first (Days 1–2), then the data layer (PostgreSQL, Redis, Redpanda), then the API Gateway and User Service. Until the Gateway is live with JWT, nobody can do real API integration — so Vlad and Rareș work in isolation with mock data.
- **Rareș** works offline first. LLM prompt engineering, RAG pipeline design, and Qdrant schema can be validated locally without any running infrastructure. This is intentional: AI prompt quality is the highest-risk variable in the project, and it must be proven before being integrated into a live service. **Rareș also owns 3 backend tasks:** the shared Kafka/aiokafka boilerplate (CP-017 — Python, his domain), the Learning Path REST API endpoints (CP-050 — FastAPI CRUD for learning paths and quizzes), and the Agent Orchestrator's monitoring HTTP API (CP-051 — workflow status, history, and admin endpoints).
- **Vlad** builds the UI shell. All pages are built against mock data/fixtures first. This lets him move fast without waiting for APIs. Real integration happens in Weeks 3–4 once the backend contracts are stable.

### Dependency Hierarchy (Critical Path)

```
CP-001 (Docker Compose)
  └─► CP-003 (Redpanda)
  └─► CP-002 (PostgreSQL)
        └─► CP-006 (User Service Auth)

                                            └─► CP-031 (HR Interview Agent)

```
